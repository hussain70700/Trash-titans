Purpose

The problem we saw, why we took it on, and how we built BinSense

The problem in society

In many cities, including ours, waste collection runs on fixed routes and schedules. Trucks visit every bin whether it is empty or full.

The result is two problems at once: some bins overflow between visits, spilling waste onto the street, attracting pests and spreading odour, while other stops are wasted trips that burn fuel and time. Nobody has live information about which bins actually need attention.

Why we chose it

The theme asks for ICT that makes cities smarter and living healthier and more sustainable. Waste is something everyone sees every day, it affects public health, and the fix is mostly about having the right information rather than building new infrastructure.

It also suits a small, low-cost ESP32 prototype that can grow into a paid service for societies, markets and campuses.

How we did it

An ultrasonic sensor in the bin lid measures how full the bin is. An ESP32 turns that into a percentage, shows it on a small OLED at the bin and sends it over Wi-Fi to the cloud.

A dashboard flags any bin above 80% and gives collectors a route list, so they visit only the bins that need emptying. Clients subscribe per bin and pay by JazzCash or Easypaisa.

Design

How data moves through the system

1 HC-SR04 sensor2 ESP32 + OLED3 Wi-Fi (MQTT/HTTP)4 Cloud5 Dashboard + alerts6 JazzCash / Easypaisa

At the bin

The ESP32 wakes from deep sleep, triggers the ultrasonic sensor, converts distance to fill percentage and shows it on the OLED.

In the cloud

Each reading is stored with a timestamp. Above 80% the bin is flagged full and an alert is raised.

For the client

A dashboard shows every bin, a collector route list and the monthly payment status.
